# Empacotamento Linux — Mycellia

Cada Release do Mycellia (`github.com/o-felipe-fula/Mycellia/releases`) sobe os bundles Linux
gerados pelo `tauri-action` no job `build` (`.github/workflows/build.yml`). Qual arquivo baixar
depende da distro:

| Distro | Arquivo | Observação |
|---|---|---|
| Debian, Ubuntu e derivadas | `Mycellia_<versão>_amd64.deb` | `sudo apt install ./Mycellia_<versão>_amd64.deb` (ou `dpkg -i` + `apt --fix-broken install`). Dependências `libwebkit2gtk-4.1-0`/`libgtk-3-0` são resolvidas automaticamente pelo `.deb` (gerado pelo bundler do Tauri v2). |
| Fedora, openSUSE e derivadas | `Mycellia-<versão>-1.x86_64.rpm` | `sudo dnf install ./Mycellia-<versão>-1.x86_64.rpm` (Fedora) ou `sudo zypper install ./Mycellia-<versão>-1.x86_64.rpm` (openSUSE). Dependências declaradas: `webkit2gtk4.1`, `gtk3` (nomes de pacote Fedora — openSUSE pode diferir; ver seção abaixo). |
| Arch, CachyOS, Manjaro e derivadas | pacote AUR `mycellia-bin` | `paru -S mycellia-bin` ou `yay -S mycellia-bin`. Baixa o `.deb` da Release mais recente e extrai o binário/`.desktop`/ícones com `bsdtar` — ver `packaging/aur/PKGBUILD`. |
| Qualquer distro Linux x86_64 (universal) | `Mycellia_<versão>_amd64.AppImage` | `chmod +x` + executar direto, sem instalar. Autocontido (WebKitGTK, GTK3 e o `.desktop`/ícone vêm embutidos pelo bundler — ver nota abaixo). Só sai do CI (GitHub Actions, runner `ubuntu-latest`); build local em Arch falha por causa da ferramenta externa `linuxdeploy` (ver `Specs/Registro_Execucao.md` §63). |

## Decisões tomadas nesta fatia (D8.3) e por quê

- **`.deb` não leva `bundle.linux.deb.depends` manual.** O bundler do Tauri v2 já declara
  `libwebkit2gtk-4.1-0` + `libgtk-3-0` automaticamente no control file (e `libappindicator3-1`
  só se o app usar bandeja do sistema — o Mycellia não usa: sem feature `tray-icon` no
  `Cargo.toml`). Fonte: `tauri-docs` (`src/content/docs/distribute/debian.mdx`, branch `v2`) —
  "The stock Debian package generated by the Tauri bundler has everything you need [...]
  specifying the dependencies `libwebkit2gtk-4.1-0` and `libgtk-3-0`, along with
  `libappindicator3-1` if your app uses the system tray." Confirmado também lendo o bundler:
  `crates/tauri-bundler/src/bundle/linux/debian.rs` monta o `Depends:` só a partir de
  `settings.deb().depends` (vazio por padrão) + a lista automática hardcoded no gerador do
  control file.
- **`.rpm` PRECISA de `bundle.linux.rpm.depends` manual** — ao contrário do `.deb`, o bundler
  RPM do Tauri v2 **não infere nenhuma dependência automaticamente**. Conferido lendo o código-fonte:
  `crates/tauri-bundler/src/bundle/linux/rpm.rs` só adiciona `Requires:` a partir do que estiver
  em `settings.rpm().depends` (`for dep in settings.rpm().depends...unwrap_or_default()` — lista
  vazia se não configurado). Por isso `tauri.conf.json` agora declara
  `bundle.linux.rpm.depends: ["webkit2gtk4.1", "gtk3"]`, espelhando exatamente o que o `.deb`
  adiciona sozinho (sem bandeja do sistema = sem appindicator). Nomes de pacote Fedora
  (`webkit2gtk4.1-devel`/`libappindicator-gtk3-devel`/`librsvg2-devel`/`openssl-devel` são os
  nomes **-devel**, de build; os runtime, sem `-devel`, são `webkit2gtk4.1` e `gtk3` — fonte:
  `tauri-docs` `src/content/docs/start/prerequisites.mdx`, seção Fedora). **openSUSE usa nomes de
  pacote diferentes dos de Fedora** (ex.: `libwebkit2gtk-4_1-0` em vez de `webkit2gtk4.1`) — o
  RPM gerado pode não resolver essas dependências automaticamente no openSUSE; isso é uma
  limitação conhecida do bundler RPM do Tauri (orientado a Fedora), documentada aqui e não
  resolvida nesta fatia (fora do teto do D8.3).
- **`bundle.linux.rpm.release`/`epoch` não foram setados.** `release` já tem default `"1"`
  (`default_release()` no `tauri-utils`) e `epoch` default `0` — não havia necessidade real de
  sobrescrever (spec pedia só "se necessário").
- **AppImage não ganhou `bundle.linux.appimage` novo.** Confirmado lendo
  `crates/tauri-bundler/src/bundle/linux/appimage/linuxdeploy.rs`: a geração do AppDir chama
  `debian::generate_data()` (a MESMA função que monta o `.desktop` + ícones do `.deb`) antes de
  rodar o `linuxdeploy`, e copia o ícone maior + `usr/share/applications/<nome>.desktop` pro
  AppDir automaticamente. Ou seja, `.desktop` e ícone já vêm embutidos de graça a partir do
  `bundle.icon`/`productName`/`shortDescription` já configurados — nada a adicionar.
- **`bundle.category`/`shortDescription`/`longDescription`** entraram porque alimentam o
  `.desktop` (category) e a `Description:` do `.deb`/`.rpm` (short+long description) — confirmado
  no schema `crates/tauri-utils/src/config.rs` (`BundleConfig`, comentários de cada campo) e no
  gerador do control file do `.deb` (`debian.rs`, `writeln!(file, "Description: {short_description}")`
  + as linhas seguintes do `long_description`).

## O que o Felipe precisa configurar pra ligar o AUR (`mycellia-bin`)

O job `aur` em `.github/workflows/build.yml` fica **desligado por padrão** (gate duplo: variável
de repositório `PUBLISH_AUR` E secret `AUR_SSH_PRIVATE_KEY`) até a primeira release pública sair
do modo pré-release. Pra ligar:

1. Criar uma conta em [aur.archlinux.org](https://aur.archlinux.org/register) (se ainda não tiver).
2. Gerar um par de chaves SSH dedicado (`ssh-keygen -t ed25519 -C "mycellia-aur"`, sem senha) e
   cadastrar a **chave pública** na conta AUR (My Account → SSH Public Key). O pacote `mycellia-bin`
   precisa existir no AUR antes do primeiro push automático — publicar a versão 0 manualmente
   (`git clone ssh://aur@aur.archlinux.org/mycellia-bin.git`, colar os 3 arquivos deste diretório,
   commit, push) evita o job de CI tropeçar num repositório AUR inexistente.
3. No GitHub, `Settings → Secrets and variables → Actions`:
   - **Secret** `AUR_SSH_PRIVATE_KEY` = a **chave privada** gerada no passo 2.
   - **Variable** `PUBLISH_AUR` = `true`.
   - **Variables** `AUR_USERNAME` e `AUR_EMAIL` = identidade de commit a usar nos pushes
     automáticos pro repo AUR (não precisam ser secretas; qualquer nome/e-mail serve, viram o
     autor dos commits `Update PKGBUILD and .SRCINFO...` no AUR).
4. Depois disso, todo push de tag `v*` roda o job `aur`: ele ajusta o `pkgver` do
   `packaging/aur/PKGBUILD` pra bater com a tag, deixa a action
   `KSXGitHub/github-actions-deploy-aur` rodar `updpkgsums` (recalcula o `sha256sums` a partir do
   `.deb` real já publicado na Release pela mesma run) e faz o push pro `ssh://aur@aur.archlinux.org/mycellia-bin.git`.
